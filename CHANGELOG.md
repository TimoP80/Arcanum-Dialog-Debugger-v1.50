# Changelog

All notable changes to this project are documented here.

## [v0.3.0] - 2026-06-04

### Added
- `Preferences.pas` and `Preferences.dfm` — modal preferences dialog (`TfrmPreferences`) opened from the new `Preferences...` button on the main toolbar
- `TPreferences` class for reading/writing `DialogDebugger.ini` next to the executable (`[Paths]`, `[Debug]`, `[Editor]` sections)
- `Preferences...` button on `TfrmMain` that opens the preferences dialog (OK / Cancel / Apply)
- Arcanum install path picker — `TEdit` with `Browse...` that calls `SelectDirectory`
- Last DLG folder picker — same pattern, applied as `OpenDialog1.InitialDir` and auto-saved after a successful `.dlg` load
- Verbose debug toggle — preference is persisted in `DialogDebugger.ini`; ready to wire into `ArcanumSCRLib.ConsoleDebug` once the undeclared `verbosedebug` global in `ScriptEdConfig` is resolved
- Debug logging toggle — when disabled, `mmoDebug` stays empty
- `Line number step` `TSpinEdit` (1–1000, default 20)
- `ModuleManager.SetModuleRoot` — new public method; main form calls it with the configured Arcanum path before showing the module manager
- `DialogDebugger.dpr` and `DialogDebugger.dproj` updated to include the new `Preferences` unit

### Changed
- `ModuleManager.pas` — `FModuleRoot` now set via `SetModuleRoot`; `ScanModules` only runs when a valid root is configured
- `MainForm.pas` — adds `FPreferences`, `ApplyPreferences`, `btnPreferencesClick`; `LogDebug` honors the debug logging toggle; module manager launch warns and aborts if the Arcanum path is not configured

### Build
- `StateWatch.dfm` / `StateWatch.pas` — Delphi normalized default properties and added `Vcl.ComCtrls` to the `uses` clause (required for the existing `TPageControl` references)
- `DialogDebugger.res` — regenerated by the build (now includes the application icon)
- `.gitignore` — ignores `__history/`, `*.otares`, and `*.drescan` (additional Delphi build artifacts)

## [v0.2.0] - 2026-06-03

### Added
- Full Arcanum native dialog line parser (`DialogueParser.pas`)
  - NPC lines: `{N}{Male}{Female}`
  - PC lines: `{N}{Text}{Tests}{R}{Results}`
  - Generated-dialog commands (A–Z, Q, I, R, G, M)
- `TDialogueNode` with `NPCLines`, `PlayerOptions`, `GeneratedOptions`, `LineMap`
- `TDialogueParser.ParseDialogue` and helpers
- `DialogEngine.EvaluateTests` — all EventScripts test codes ($$, al, ar, ch, fo, gf, gv, ha, ia, in, lc, le, lf, ma, me, na, ni, pa, pe, pf, ps, pv, qa, qb, qu, ra, re, rp, rq, ru, sc, sk, ss, ta, tr, wa, wt)
- `DialogEngine.ExecuteResults` — all EventScripts result codes ($$, al, ce, co, et, fl, fp, gf, gv, ii, in, jo, lc, lf, lv, mm, nk, np, or, pf, pv, qu, re, ri, rp, rq, ru, sc, so, ss, su, tr, uw, wa, xp)
- Engine state fields: `FPlayerLevel`, `FMagicAptitude`, `FTechAptitude`, `FCurrentArea`, `FCurrentNPC`, `FRumors`, `FPlayerReputations`
- `DialogEngine.FindLineInNodes` for `TargetLine` resolution
- `TDialogEngine.TSkill` enum mapping 0–15 → skill names
- Generated-option expansion in `EvaluateOptions` (Q: handled)

### Changed
- `DIalogueParser.pas` → renamed to `DialogueParser.pas` (correct casing)
- `DialogDebugger.dpr` and `.dproj` updated to reference `DialogueParser.pas`
- `EvaluateTests` and `ExecuteResults` rewritten from stub to full implementation
